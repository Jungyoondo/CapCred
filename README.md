# CapCred — 해야 하는 일을, 공공 기록으로 대신

> 2026 2학기 제출물. "이래서 이걸 해 줘" 한 줄이면 에이전트가 공공데이터와 재무제표로 결과물을 만들고, 사람은 확인하고 서명만 한다.
> 첫 제품은 프랜차이즈 본부가 해마다 4월 말까지 고쳐 내야 하는 정보공개서다(지금은 가맹거래사에게 건당 30만 원, 5~10일). CapCred = Capacity(일을 맡아 해내는 역량) + Credibility(검정된 근거), 약자 Compliance Agent for Public-data Checks, Records, Evidence & Documents.

## 핵심 근거 (모두 사전 등록 → 실행 → 기각까지 공개, `scoreboard/HYPOTHESES.md`)
- 에이전트가 미리 채운 서울 매장 수는 작년 숫자 복사보다 오차 16.8% 작고, 변동 경보의 83.2%가 실제 신고와 같은 방향이었다(외식 879개 브랜드, 2019~2025, H-2026-10-AC).
- 지난 시즌(회계년도 2025) 재현: 서울 외식 537개 브랜드, 확인할 매장 변동 1,995건, 경보 150개, 공개된 신고 대비 경보 적중 88%.
- 기각도 그대로: "정보공개서는 1년 늦다"(6.4% < 10%), "장부와 상가 목록의 불일치가 폐업을 미리 안다"(1.5배 < 2배), 개별 가게 신용점수(AUC 0.56~0.62).
- 전체: 사전 등록 검정 14건, 세부 가설 38개(성립 19, 기각 14, 보류 5). 실전 봉인 1건(2026 회계년도 예상값 334개 브랜드)은 2027-10-31에 채점한다.

## 동작하는 것
- `code/caed/concierge.py`: 요청 한 줄 → 레시피 6개(정보공개서 정기변경, 인근 가맹점 10곳 문서, 사업장 실재·이력 확인서, 인허가 대장 정비 목록, 동네 업종 기준선, 회사 재무·공시 요약) → 결과물 + 작업 기록. 원천 데이터는 포함하지 않는다(서울 열린데이터·공정위 가맹정보·OpenDART API 키로 다시 받는다).
- 결과물에 상호가 들어가는 실행 결과는 로컬에만 둔다. 공개물의 브랜드는 모두 가명이다.

## 폴더
- `report/` 보고서 PDF·원본 HTML·시연 화면·숫자 대조표
- `videos/` 영상·자막·대본

- `scoreboard/` 사전 등록 가설(사업 부분)과 봉인 원장
- `code/` 사업 코드(caed 에이전트·검정, 사업 사이트, 영상·보고서 렌더)
- `results/` 위 숫자의 원천 요약 결과
- `history/` 이전 단계(신용캐드 대안 신용평가, dintel 상장사 조기경보) 보고서와 대본 - 방향 전환의 기록
